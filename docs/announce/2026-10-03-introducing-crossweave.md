## Vietnamese (Facebook / LinkedIn)

**crossweave — chạy N agent song song trên một repo mà không dẫm chân nhau**

Mở 3–4 terminal, mỗi cái một AI agent sửa cùng một repo, cuối ngày ngồi merge bằng tay và cầu nguyện?
Mình viết crossweave để bớt khổ đoạn đó.

Ý tưởng gọn: **mỗi session là một git worktree + shell của riêng nó** — như tmux window, nhưng mỗi cái
một branch. Gõ gì trong đó là tuỳ bạn: `claude …`, `codex …`, wrapper của bạn, hay `npm run dev`.
crossweave không chọn, không cấu hình, không tự launch agent.

Daemon chạy nền lo phần khó:
- **Cô lập cả runtime, không chỉ file** — mỗi session có port block riêng (`$PORT`), cache dir, tên DB/Docker tuỳ chọn.
- **Khép vòng lặp** — trial-merge các session với nhau ở nền, nên `cw land` cho biết cái nào an toàn và nên merge theo thứ tự nào.
- **Cho thấy sẽ mang gì vào** — diff từng session so với base trước khi land.

**Cockpit** (app Electron, macOS arm64): một sidebar liệt kê mọi project và session, mỗi dòng tự nói đang
chạy / chờ bạn / xong / lỗi — suy ra từ chính shell, không cần cấu hình. Kèm:
- **prompt composer** (⌘⇧P) — viết một prompt, gửi nhiều session cùng lúc
- **`cw notify`** — agent tự báo "xong" / "cần trả lời" → ✓ hoặc chấm hổ phách trên dòng
- **`cw check`** — chạy test command đã trust trong worktree trước khi land
- **so sánh 2 session** cạnh nhau rồi land cái tốt hơn
- **presets** — một click ra session + terminal dev + browser trên port của nó
- **Dashboard** đĩa/RAM theo project — chỉ *đề xuất* dọn, luôn hỏi trước
- panes kiểu tmux (split, zoom, copy-mode, key-table `Ctrl-A`)

Mới trên `main` (chưa phát hành): **vòng lặp debug cho AI** — `cw hooks install claude` nối hook của chính
agent với `cw notify` để trạng thái chính xác; `cw debug` in một gói gọn (tail test lỗi, các dòng error,
diffstat, lời cuối của agent) đã lọc secret để dán cho AI; cockpit có Debug pane và Responses view cho prompt
đã gửi nhiều session.

Thẳng thắn: cockpit v1 chỉ macOS arm64 và **chưa notarize** (lần đầu mở có thể phải "Open Anyway");
Windows/Linux cockpit để sau. Một số thứ mạnh bị gỡ *có chủ đích* (collision guard, sandbox OS, remote web) —
repo ghi rõ lý do và tag cuối còn có chúng.

Cài: `curl -fsSL https://raw.githubusercontent.com/NMHx2005/crossweave/main/install.sh | sh`
(Bun ≥ 1.3.13 · macOS/Linux · MIT)

## English

**crossweave — run N coding agents on one repo without them stepping on each other**

Four terminals, four agents, one repository, and an evening of hand-merging? crossweave is my answer.

A **session is a git worktree plus your shell in it** — a tmux window where each one has its own branch.
What you type there is yours: `claude …`, `codex …`, your own wrapper, a dev server. crossweave never
picks, configures or launches an agent.

A background daemon:
- isolates **runtime**, not just files — a port block (`$PORT`), cache dir and optional DB/Docker names per session;
- trial-merges sessions against each other, so `cw land` knows what is safe and in what order;
- shows what landing would bring in before you land it.

The macOS **Cockpit** puts every session on one rail (working / waiting for you / done / failed, inferred
from the shell), with a prompt composer for several sessions at once, `cw notify` and `cw check`, side-by-side
compare, one-click presets, tmux-style panes and a resource Dashboard that only ever *proposes* clean-ups.

New on `main`, not yet released: an **AI debug loop** — `cw hooks install` for exact done/asked marks,
`cw debug` for one scrubbed bundle of why a session failed (made to paste into an AI), a Debug pane and a
Responses view.

Honest limits: cockpit v1 is macOS arm64 only and not yet notarized; no Windows. Several features were
removed on purpose (collision guard, OS sandbox, browser remote) — the repo says why.

https://github.com/NMHx2005/crossweave · MIT
