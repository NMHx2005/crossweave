# crossweave website v2 — implementation plan

> **For agentic workers:** implement task by task, tests first. Steps use checkbox syntax.

**Goal:** Rework the home page into a story-led page (how it works, grouped features, audience, proof of life, security page) and produce, edit and embed a Cursor-style demo clip with a visible cursor, a camera that zooms to the action and explanatory captions.

**Architecture:** the first version's static Bun build stays; content types gain the new fields; `home.ts` is rebuilt around them; one new docs page comes from `SECURITY.md`; the clip is made by a script that drives the real cockpit over CDP, renders frame by frame and encodes with `ffmpeg`, and its outputs are committed under `website/public/media/`.

**Spec:** `docs/superpowers/specs/2026-10-11-website-v2-design.md` (read it first; it repeats nothing below). Standing rules: the first plan's global constraints (no dependency, TypeScript strict, one logical change per commit, `feat/website` only, tests one at a time with `--max-concurrency=1` outside the sandbox, words such as `.env`/`secret` in a heredoc can be blocked: use the Write/Edit tools).

## Review focus

1. A feature newer than the latest release must never appear in a group, only in the Coming strip, and the pill and strip must vanish by themselves when the release exists (Task 3).
2. Everything new must survive with no script: the copy button hidden, the video showing its poster, nothing hidden (Task 4, Task 7).
3. The video must be honest about what it is, and reduced motion must not autoplay it (Task 4, Task 7).
4. The Vietnamese page must have every new key and read as Vietnamese, not as a calque (Task 1).
5. The build must stay byte-identical across runs and the CSP must gain only `media-src 'self'` (Task 4).

### Task 6: The clip — recorder, edit, assets

**Files:** Create `apps/cockpit/scripts/site-video.ts`, `apps/cockpit/scripts/site-video/` helpers if the script exceeds one file's readability, `website/public/media/demo.mp4`, `website/public/media/poster.jpg`, `website/public/img/step-1.png`, `step-2.png`, `step-3.png`, `website/public/img/og.png`; Modify `apps/cockpit/README.md` (one paragraph on the script).

Design of the recorder (all in one script, ~400 lines, no dependency, run outside the sandbox on a scratch HOME and project, refusing a real home like `settings-polish-check.ts` does):

- **Setup:** `seed <dir>` reuses `demo-shot.ts seed`; the app is opened by the owner/assistant with `--remote-debugging-port` and a scratch `--user-data-dir`; the script waits for the rail.
- **Stage:** it injects, once, a `#cw-stage` overlay: a full-viewport fixed backdrop (flat dark colour from the cockpit tokens plus faint diagonal warp-thread lines in `--cw-agent-claude`, `--cw-agent-codex`, `--cw-ready`, `--cw-working`), a `#cw-camera` layer to which `#app` is moved after being sized to a 1360×850 window with a 14 px radius and a deep shadow (`#app { min-height: 0 }`, then a resize event so xterm refits), an SVG cursor and a click ripple inside the camera layer, and constant-size captions and cards in a `#cw-overlay` above it. Viewport 1920×1080 at device scale 1.5 (screenshots 2880×1620, supersampled to 1920×1080 by `ffmpeg`).
- **Timeline:** data, not code: `cameraKeys: Array<{ t, x, y, z, ease }>` (focus point and zoom, eased with an expo-out/in-out between keys, zoom at most 1.6), `cursorKeys` (targets named by selector, resolved at render time to the element's centre in camera space, moved along an eased curve with a small overshoot, hover events dispatched along the path), `captions: Array<{ t0, t1, step, text }>` (fade in 0.35 s, out 0.35 s), `cards` (title and end), and `actions: Array<{ t, run }>` — real work: create three sessions through the daemon and start them, run the scripted agent scene in each, `cw notify` for the asking and done marks, make two sessions touch different files and one touch the same file as another so the trial merges report one conflict, open Changes, click the Land chip, confirm.
- **Render loop:** for frame i of N at 30 fps: `t = i / 30`; fire due actions without awaiting; one `Runtime.evaluate` sets camera transform, cursor position, ripple, caption opacities; if the cursor crosses an element, `Input.dispatchMouseEvent` mouseMoved/pressed/released at the right frames; `Page.captureScreenshot` (png, `fromSurface`); write `frames/%05d.png`. A watchdog aborts if a frame takes over 5 s.
- **Edit:** `ffmpeg -framerate 30 -i frames/%05d.png -vf "scale=1920:1080:flags=lanczos,fade=t=in:st=0:d=0.5,fade=t=out:st=<end-0.6>:d=0.6" -c:v libx264 -preset slow -crf 22 -pix_fmt yuv420p -movflags +faststart demo.mp4`; adjust CRF until the file is under 4 MB; poster from a chosen frame; three step stills from chosen frames cropped and scaled to 1600×1000 PNG (then `sips`/`ffmpeg` optimised); the OG card from the title frame with the headline set in the page by the script before its capture.
- **Checks the script makes itself:** every named target was found; the final frame count equals the plan; `ffprobe` reports 1920×1080, 30 fps, duration within 0.1 s of plan, H.264, `yuv420p`, no audio; file size under 4 MB.
